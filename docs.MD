## 1. Шаблон репозитория юр-форензики под GitVerse / GitHub

Цель:

* хранить **сырые данные**,
* фиксировать **целостность и цепочку владения**,
* отделять **аналитику/ИИ-выводы** от собственно **доказательств**,
* делать всё **машиночитаемым** для гос- и частных ИИ-систем.

### 1.1. Структура репозитория (скелет)

```text
legal-forensics-template/
├── README.md
├── REPO_MANIFEST.yml                # базовая метаинформация о репо
├── docs/                            # методика, шаблоны, пояснительные материалы
│   ├── 00_overview.md
│   ├── 01_legal_framework_ru.md     # выписка норм об электронных/цифровых доказательствах
│   ├── 02_methodology_collection.md # методика сбора
│   ├── 03_chain_of_custody.md       # методика фиксации и хеширования
│   ├── 04_ai_processing_guidelines.md
│   └── templates/

│       ├── chain_log_template.xlsx
│       └── court_bundle_structure.md
├── registry/                        # сквозные реестры по всем делам
│   ├── cases_index.csv              # список дел и их статусов
│   ├── evidence_index.csv           # каждая сущность-доказательство (ID, hash, путь)
│   ├── chain_of_custody_log.csv     # цепочка действий с объектами
│   └── integrity_checksums.json     # контрольные суммы по папкам/релизам
├── cases/

│   │   │   ├── ocr_text/            # результаты OCR

│   │   ├── 05_legal_docs/           # процессуальные документы по делу
│   │   │   ├── claims/              # иски, заявления, жалобы
```

### 1.2. Ключевые принципы организации

1. **Разделение слоёв:**

   * `01_sources_raw` — только то, что вы реально получили из внешней среды.
   * `02_tech_fixation` — доказательство того, *как* вы это получили (протоколы, хеши, отчёты сервисов автоматической фиксации).
   * `03_derived_data` — технически полезные производные (распознавание речи, OCR), но не первичные доказательства.
   * `04_ai_analysis` — интерпретации ИИ (всегда отделены от сырья).
   * `05_legal_docs` и `06_court_exports` — уже правовая работа и то, что ушло в органы.

2. **Идентификаторы и названия файлов.**
   Рекомендуемый паттерн:

   ```text
   YYYYMMDD_HHMMSS_[source]_[short-tag]_[seq].[ext]
   20251128_231530_telegram_chat-opg-x-log01.json
   20251128_231742_screen_mysite-article1.png
   ```

   Это облегчает сортировку по времени и чтение машиной.

3. **Hash-first.**

   * Для каждого файла в `01_sources_raw` и `02_tech_fixation` — SHA-256 и (по возможности) ГОСТ-хеш.
   * Отдельный файл:

     ```text
     hashes/20251128_sources.sha256
     ```
   * Хеши дублируются в `registry/evidence_index.csv`, чтобы можно было «доказать, что именно этот файл был в том самом коммите».

4. **Цепочка владения (chain of custody).**
   Формат строки в `chain_of_custody_log.csv`:

   ```csv
   record_id,evidence_id,datetime,actor,action,tool,hash_before,hash_after,comment
   1,EV-2025-001,2025-11-28T23:15:30+03:00,investigator,"captured_web",BrowserWitness 1.2,"","a1b2...", "Осмотр страницы https://..."
   ```

5. **Машиночитаемый слой.**
   `normalized_json/` и `schemas/` должны позволять любому ИИ-агенту:

   * понять тип доказательства (web_page, messenger_chat, audio_call, bank_statement и т.п.);
   * быстро получить таймлайн, участников, отношения к делу, ссылку на исходный файл и хеш.

Пример объекта:

```json
{
  "evidence_id": "EV-2025-001",
  "case_id": "2025_A40-123456_FooBar",
  "type": "messenger_chat",
  "source_system": "Telegram",
  "participants": [
    {"id": "P-01", "role": "victim"},
    {"id": "P-02", "role": "suspect"}
  ],
  "time_range": {
    "from": "2025-11-20T18:00:00+03:00",
    "to": "2025-11-20T19:30:00+03:00"
  },
  "original_files": [
    {
      "path": "01_sources_raw/messengers/20251120_telegram_export_chat-xxx.json",
      "sha256": "a1b2c3..."
    }
  ],
  "fixation": {
    "web_capture_protocol": null,
    "autofix_service_report": "02_tech_fixation/capture_protocols/20251120_fixation-service-report-001.pdf"
  }
}
```

### 1.3. README.md — скелет

Можно такой каркас (сокращённо):

```markdown
# Legal Forensics Repository Template

## 1. Назначение

- Хранение и обработка электронных/цифровых доказательств в делах `...`.
- Обеспечение воспроизводимой методики фиксации, хеширования и документирования.
- Подготовка данных для автоматизированного анализа (в т.ч. ИИ-системами госорганов и частных лиц).

## 2. Правовая рамка (РФ)

- Электронные доказательства как самостоятельный вид: ст. 71.1 АПК РФ, ст. 64.1 ГПК РФ, ст. 57.1 КАС РФ.
- Допустимость:
  - интернет-сайты, переписка в мессенджерах/почте, аудио/видеозаписи, метаданные;
  - документы, заверенные ЭП, протоколами осмотра (нотариус, специалисты, сервисы автоматической фиксации).
- Применимость репозитория:
  - репозиторий фиксирует происхождение и целостность файлов;
  - отдельные протоколы осмотра и отчёты сервисов автоматической фиксации прилагаются в `02_tech_fixation/`.

## 3. Методика конвейерной обработки

1. **Подготовка среды.**  
   Синхронизация времени, фиксация версии ОС/ПО, настройка записи экрана.

2. **Сбор сырья (`01_sources_raw/`).**  
   - сохранение страниц (html/pdf/mhtml);
   - экспорт переписки;
   - скачивание медиафайлов;
   - документирование того, кто и когда выполнял действия.

3. **Фиксация и хеширование (`02_tech_fixation/`).**  
   - расчёт хешей, сохранение в `hashes/`;
   - формирование протоколов осмотра, скринкастов;
   - при наличии — отчёты сервисов автоматической фиксации.

4. **Нормализация (`03_derived_data/normalized_json/`).**  
   - приведение разных форматов к единому JSON;
   - заполнение полей по схемам `schemas/`.

5. **ИИ-анализ (`04_ai_analysis/`).**  
   - извлечение фактов и сущностей;
   - построение графов, таймлайнов;
   - оценочные выводы ИИ — *как отдельный слой*, не подменяющий мнение эксперта/следствия.

6. **Формирование пакетов для суда (`06_court_exports/`).**  
   - генерация PDF-подборок с описью;
   - выгрузка перечней доказательств с хешами;
   - подготовка текстов ходатайств о приобщении электронных доказательств и пояснений по методике.

## 4. Интеграция с государственными и частными ИИ-системами

- Использование JSON-схем для автоматической индексации.
- Возможность построения RAG-слоя поверх репозитория.
- Поддержка выгрузки в форматы:
  - CSV (для импорта в аналитические системы судов/следствия),
  - NDJSON,
  - ZIP-архивы по делу с manifest-файлом.
```

Это README можно донаполнить под конкретные статьи УК/УПК, под практику автоматической фиксации и под ваши собственные протоколы.
